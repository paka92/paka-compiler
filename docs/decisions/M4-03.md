# M4-03 · The agent tool interface

Status: approved by the owner on 2026-10-15.

Base: the recorded M4-03 page in DECISIONS.md. All five points and the points settled without asking
**stand** as recommended there. This record writes them out as one table per call and gives an
example exchange for every call, every find field and every error kind. Version 1.

## 1. Points

| Point | Ruling |
|---|---|
| 1.1 Transport | JSON lines on stdio. `paka serve <program>` serves one file or directory for the session. |
| 1.2 Base version | The first 12 hex digits of the SHA-256 of the definition's canonical text. |
| 1.3 Edit | One definition per call; `base` null adds, `text` null deletes; an optional `run` runs right after. |
| 1.4 Shape query | `takes` and `gives`, exact, over the program's own fn and view definitions. |
| 1.5 View budget | The body is always whole; signatures of what it uses are dropped first. |

## 2. Envelope

- UTF-8, one JSON object per line, no line break inside an object. Requests are handled one at a
  time in arrival order; there is no handshake.
- Every request carries `v`, `id` and `call`; every reply carries `v`, the request's `id` and `ok`.
  `id` is any JSON number or string and is echoed unchanged.
- A failure is `ok: false` with `error`: `kind`, `message`, and the extra fields its kind lists in
  section 3.5. Nothing is stored by a failed call.
- `v` is 1. Adding an optional field or a new call keeps it; removing a field or changing a meaning
  raises it.
- A field a call does not know is refused (`bad_request`), so a misspelt field never passes silently.
- The server holds a standard-library file lock on the program; a second server is refused. If a file
  does not parse, the server prints the errors and does not start. It assumes it alone writes the
  program's files; after git or a person changes them, restart it.

**Versions.** A version hashes the UTF-8 bytes of the canonical `text` exactly as a reply carries it:
comments included, no line feed after the last line. For a type or enum the `sig` is the whole text,
so its version is the hash of `sig`. Every version below was computed with the system's `sha256sum`:

```
printf '%s' 'type Tally { words: Int = 0 }' | sha256sum | cut -c1-12
bb18fead002b
```

**Tokens.** A budget counts the whole reply line: bytes divided by 3, rounded up (M2-18), until M3
records real tokens.

**Error objects** are M2-04's JSON object with the same keys. Lines, columns and offsets count from
the start of the `text` they point into; `file` is null, because the agent never sees the file.

## 3. Calls

### 3.1 find

| Field | Type | Required | Meaning |
|---|---|---|---|
| `name` | string | no | Exact name, or a pattern where `*` stands for any run of characters. |
| `users_of` | string | no | Definitions that directly use this definition, variant or built-in. |
| `takes` | list of strings | no | Types the parameters must include, in any order; a type listed twice needs two parameters. |
| `gives` | string | no | The result type. |
| `kind` | string | no | `type`, `enum`, `fn`, `view`, `example`, `app` or `builtin`. |
| `failing` | bool | no | True lists definitions that do not check now. |
| `budget` | int | no | Tokens, default 1,000. |
| `after` | string | no | Continue after this name. |

Fields given together must all hold. Type text in `takes` and `gives` is parsed and printed
canonically before it is compared, so spacing does not matter; `inout` is not part of a type.
`takes` and `gives` match only the program's own fn and view definitions.

Reply: `found`, a list of entries sorted by name in byte order, and `more`, the count left out by
the budget. An entry is `name`, `kind`, `sig`, `version`. `sig` is the whole text for a type or enum
and the header without the brace for the rest. A built-in has kind `builtin` and version null.

### 3.2 view

| Field | Type | Required | Meaning |
|---|---|---|---|
| `name` | string | yes | The definition. |
| `budget` | int | no | Tokens, default 2,000. |

Reply: `name`, `kind`, `version`, `text` (canonical, whole), `uses`, `more`, `errors`. `uses` holds
find entries for the definitions the text names, in first-named order, built-ins left out, while the
reply fits the budget; `more` counts those left out. `errors` are the definition's current errors.
If the body alone is over budget the call fails with kind `budget`.

### 3.3 edit

| Field | Type | Required | Meaning |
|---|---|---|---|
| `name` | string | yes | The definition. |
| `base` | string or null | yes | Its current version; null adds a new definition. |
| `text` | string or null | yes | The new text, exactly one definition named `name`; null deletes. |
| `run` | object | no | `app`, `args`, `limit_ms`, `max_bytes`, as in a run call. |

Refused, nothing stored, when the base is stale, the name exists on an add, or the text does not
parse as exactly one definition named `name`. Otherwise stored, even with type errors or broken
users.

Reply: `name`, `version` (null after a delete), `text` (the stored canonical text), `errors` (this
definition's own), `broke` (other definitions that no longer check because of this edit),
`installed`, and `run` when one was asked for. `installed` is true when the runnable version, the
last one in which every definition checks, now includes this edit. When it is false no run happens
and `run` is null.

### 3.4 run

| Field | Type | Required | Meaning |
|---|---|---|---|
| `app` | string | yes | The app to run. |
| `args` | list of strings | no | Arguments, default none; they reach the first message as M2-15 rules. |
| `limit_ms` | int | no | Default 10,000. Past it the run stops: `stopped` is `"time"`, `status` null. |
| `max_bytes` | int | no | Default 16,000. Each output stream is cut there and `stopped` is `"output"`. |

Runs the last version in which every definition checks, with the app's grants as written, in the
server's working directory, with empty standard input.

Reply: `run`: `stdout`, `stderr`, `status` (M1-06 and M2-15), `trap` (M2-06's fields, or null) and
`stopped` (null, `"time"`, `"output"`, or `"crash"` when the runner died; M4-04).

### 3.5 Error kinds

| Kind | When | Extra fields |
|---|---|---|
| `bad_request` | Not a JSON object (`id` null), a missing or unknown field, a wrong type. | |
| `bad_version` | `v` is not one the server speaks. | |
| `unknown_call` | `call` is not find, view, edit or run. | |
| `not_found` | No definition by that name. | |
| `stale_base` | `base` is not the current version. | `version`, `text`: the current ones |
| `name_taken` | `base` is null and the name exists. | |
| `parse` | `text` does not parse. | `errors`, pointing into the text as sent |
| `not_one_definition` | `text` holds no definition or more than one. | |
| `name_mismatch` | `text` defines another name. | |
| `budget` | A view's body alone is over its budget. | `needs`: the tokens it needs |
| `no_app` | No app by that name. | |
| `not_runnable` | No version has checked yet. | |

## 4. Example exchanges

`words.txt` beside it. Exchanges 1 to 17 are one session in id order; each error exchange stands
against the state after 17. Built-in names (`len`, `words`, `split`) follow the interpreter today.

### 4.3 Errors

**bad_request: unknown field**

```
> {"v":1,"id":20,"call":"find","nmae":"update"}
< {"v":1,"id":20,"ok":false,"error":{"kind":"bad_request","message":"find has no field `nmae`"}}
```

A line that is not a JSON object:

```
> find update
< {"v":1,"id":null,"ok":false,"error":{"kind":"bad_request","message":"a request is one JSON object per line"}}
```

**bad_version**

```
> {"v":2,"id":21,"call":"find","name":"update"}
< {"v":1,"id":21,"ok":false,"error":{"kind":"bad_version","message":"this server speaks version 1"}}
```

