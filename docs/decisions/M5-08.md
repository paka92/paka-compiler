# M5-08 · Elements, drawing stack, crates, font, screen reader and IME

Status: approved by the owner on 2026-10-26.

Base: the library trial in `trial/gui` and its report, docs/results/M5-08.md. DECISIONS.md holds no
recommended page for M5-08. The starting points were the paper's sections 3.3 and 8, the crates
the M5 plan names, and the trial. Where a choice had a smaller or safer option, that option was
taken; each such point says why.

## 1. Points

**1.1 Elements are built from scratch on drawing and text libraries, not on a toolkit.**

A toolkit such as Slint or Xilem would bring its own element model, looks, focus and update cycle.
M5-02's path ids, M5-04's fixed looks and M5-06's two back ends would then have to be fitted
around it. The trial drew M5-04's Input and Button exactly in under 300 lines. M5-17 to M5-19 and
M5-31 to M5-35 stand as cut.

**1.2 The stack.**

- winit opens the window and delivers input.
- softbuffer presents frames.
- vello_cpu draws on the CPU.
- parley does shaping, line breaking and layout.
- accesskit and accesskit_winit bridge the element tree to AT-SPI.
- Only Wayland is supported: X11 stays out, as the M5 plan says.

**1.3 The crates.** The direct crates are pinned exactly, with default features off:

| Crate | Version | Features |
|---|---|---|
| winit | 0.30.13 | `rwh_06`, `wayland`, `wayland-dlopen` |
| softbuffer | 0.4.8 | `wayland`, `wayland-dlopen` |
| vello_cpu | 0.3.0 | `std`, `text`, `u8_pipeline` |
| parley | 0.12.0 | `std` |
| accesskit | 0.25.2 | defaults |
| accesskit_winit | 0.34.2 | `accesskit_unix`, `async-io`, `rwh_06` |

- **The full list** is the 170 entries this record adds to `.cargo/approved-crates.txt`, plus 15
  that were already there. 185 outside crates are built on Linux.
- **Stubs.** 111 crates that the lock names only for other systems are vendored as manifests with
  no code and listed in `.cargo/stubbed-crates.txt`. `paka/tests/vendored.rs` checks that each one
  is empty.
- **PNG takes no crate.** A standard-library encoder, `trial/gui/src/png.rs`, writes stored deflate
  blocks. vello_cpu's `png` feature would add png, flate2, miniz_oxide and their dependencies for
  smaller screenshot files. The smaller crate list was taken: a screenshot is about 4 bytes per
  pixel, which Look can carry.
- **No Adwaita frame.** winit's Adwaita frame is left out (no `wayland-csd-adwaita`), since it would
  add a font rasteriser.

**1.4 The default font is Noto Sans Regular, shipped with Paka.** No system font is looked up:
parley's `system` feature and fontconfig stay out.

- A system lookup would make M5-05's measured widths depend on the machine. A shipped font makes
  one tree give one layout everywhere, so the shipped font was taken.
- The font file and its OFL-1.1 notice are added with M5-10 and M5-32. Until then, the trial reads
  the copy a GNOME system installs.

**1.5 Screen reader: yes in M5.** The trial gave an AT-SPI client the window, the entry, the button
and the label with roles, names and bounds. The client's click on the button reached the app. The
cost is about 64 crates (10 MB) for the bridge. M5-39 and M5-40 are in, and the exit check gains a
clause: the M5-40 script passes on both samples. This reopens M5-04's focus rule, which is ruled
in section 2.

**1.6 IME: yes in M5.** On GNOME, text-input-v3 enabled IME for the focused window, and winit
delivers preedit and commit. A scripted run could not send composed keys to the window, so M5-37's
hand check with IBus is the proof. The exit check gains a clause: one composed word typed in the
to-do sample's Input arrives as one commit.

## 2. Rules that follow

- M5-04 point 1.4 becomes the following:
  - Inputs and Buttons take focus.
  - A click moves focus only to an Input.
  - Tab and Shift+Tab move focus through Inputs and Buttons in tree order and wrap around.
  - Enter or Space on a focused Button clicks it.
  - A focused Button draws M5-04's focused border, 2 units in #0060DF.
  - Enter in an Input still does nothing.
- An AccessKit Focus action follows the same rule as Tab. An AccessKit Click on a Button sends its
  message without moving focus.
- The app sets the IME cursor area only when the cursor moves. It drops a preedit equal to the
  current one: every area change makes the input method resend its preedit, and the trial repainted
  without end until both rules were in.
- A test that checks the AT-SPI bridge runs on a private session bus with accessibility switched on
  there. The desktop's setting is never changed.
- The window uses winit's plain fallback frame on GNOME. A title bar drawn by Paka or the Adwaita
  frame can be added later with its own ruling.
- A crate added after this record still needs M4-06's approval. A version bump is a new entry.
- Apache-2.0 and Unicode-3.0 notices, and the font's OFL notice, go into a binary release's
  license file. accesskit_winit ships no license file, so its notice is taken from upstream.
- `trial/gui` stays outside the workspace as the record of this trial. M5-35 and M5-33 may take
  code from it.
