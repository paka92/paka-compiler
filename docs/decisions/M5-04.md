# M5-04 · The elements M5 builds and their arguments

Status: approved by the owner on 2026-10-13.

Base: the recorded M5-04 page in DECISIONS.md. All five points **stand** as recommended there.

## 1. Points

**1.1 Five elements:** `Text`, `Button`, `Input`, `Row`, `Col`. Both samples and the exit check use
only these; the to-do's done mark is a Button.

**1.2 Table defaults may be left out.** Only arguments with a default in the element table may be
left out; written ones keep table order, `key:` last. In M5 the defaults are `gap:` (0) and `key:`
(none), except that an Input's key must be written.

```
Col() {
  Row(gap: 8) {
    Button("-", on: Dec)
    Button("+", on: Inc, key: "inc")
  }
}
```

**1.3 No look arguments.** Each element has one fixed look; `gap:` is the only layout argument.

**1.4 Only an Input takes focus,** and only a click on an Input moves it. A click on a Button, a
Text or empty space leaves focus where it is. Tab does nothing.

**1.5 The other elements are recorded as open,** with no milestone and no names fixed. The paper's
"about 20" is an open number.

## 2. The elements

| Element | Arguments | Children, state, focus | Width | Look |
|---|---|---|---|---|
| `Text` | `text`, `key:` | none | fill | 14-unit font, 20-unit lines, black on white, left-aligned, wrapped |
| `Button` | `label`, `on:`, `key:` | none; sends `on` on click | hug | one line, 12 units left and right, 6 above and below, fill #E6E6E6, border 1 #808080, corners 4 |
| `Input` | `text`, `on_change:`, `key:` (required) | holds cursor, selection, preedit; takes focus | fill | 32 high, text in by 8, fill white, border 1 #808080, or 2 #0060DF when focused; cursor 1 black; selection #B4D5FE |
| `Row` | `gap:` (0), `key:` | child block; left to right | fill | draws nothing |
| `Col` | `gap:` (0), `key:` | child block; top to bottom | fill | draws nothing |

## 3. Rules that follow

- `Text` takes only a String. `on_change:` takes a variant with exactly one String field.
- A negative literal gap is a check-time error; a negative computed gap is a failed-assertion trap
  in the view.
- The table holds, per element, the child-block, needs-key, takes-focus and width-class marks, and
  per argument its type and default or none.
- A placeholder draws a dashed #808080 border around its name, sized like a Button with that label.
  An error node draws its message wrapped on #FFE0E0 with a 1-unit #C00000 border and 6 units
  inside. Neither can be written in a view; a click on either does nothing.
- A click is a press and release of the main button on the same element; the message is sent on
  release. No hover or pressed look.
- Enter in an Input does nothing; Tab is dropped. An `on_submit:` argument can be added later.
- A line break in a Button label or an Input's text is drawn as a space.
- No hint text, disabled form, password field or length limit in M5.
- The paper's `list` and `canvas` are not built; a list element built later needs a name other than
  `List`.
- Not decided: checkbox, radio, drop-down, slider, multi-line editor, scrolling container, lazy
  list, grid, layered stack, spacer, divider, picture, icon, canvas, progress bar, tabs, dialog,
  menu, tooltip, link.
- When the paper is next revised, its "about 20" should say open, with five built in M5.
