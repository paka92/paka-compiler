# M5-06 · UI example functions, the tree text form and hole status

Status: approved by the owner on 2026-10-13.

Base: the recorded M5-06 page in DECISIONS.md. All eight points **stand** as recommended there.

## 1. Points

**1.1 A `Ui` value, changed in place.** `ui_start(app)` gives a running app with no window. Action
functions take it as `inout`, read functions read-only. The example ends in a Bool.

```
example inc_once {
  var ui = ui_start(counter)
  ui_click(&ui, "#1/#1")
  ui_text(ui, "#0") == "1"
}
```

**1.2 A path is a String.** Steps from the root joined by `/`: an Int key as its digits, a String
key in single quotes, a place number as `#n`. The root is the empty string. A badly formed literal
path is a check-time error; a missing element is found at run time.

```
ui_click(&ui, "'new'")             // String key "new"
let title = ui_text(ui, "7/#1")    // row with Int key 7, its second line
let t = ui_text(ui, "{id}/#1")     // built from an Int value
```

**1.3 Tree text: one line per node, indented by two spaces.** Kind, step (none for the root), the
shown text in double quotes, the `name=value` fields, then `focus` if focused. A placeholder is
`Hole`, an error node `Error`.

```
Col gap=8
  Input 'new' "mil" cursor=3 on_change=Draft focus
  Button #1 "Add" on=Add
  Row 7 gap=8
    Button #0 "[ ]" on=Toggle(7)
    Text #1 "buy milk"
  Error 8 "duplicate key 8: 2 children of Col"
  Hole #4 footer
```

**1.4 The tree shows all the view passed,** messages included, plus cursor, selection, preedit and
focus. Defaults and an empty selection or preedit are not printed.

**1.5 Three readers:** `ui_tree` gives the whole tree text, `ui_text` the text one Text, Button or
Input shows, `ui_has` whether an element is there. App state is not readable through a `Ui`.

**1.6 A hole counts only if touched.** The example is unfinished if it clicks, reads or tests a
placeholder, calls `ui_tree` while one is shown, or reaches a hole in a handler or view.

**1.7 A trap ends the example** with M2-06's trapped status, or unfinished if it came from a hole.
A frame holding an error node ends it as fail.

**1.8 Typing goes to the focused input.** `ui_type` sends the text one code point at a time. With
no focused input it is a failed-assertion trap.

## 2. Rules that follow

- The functions: `ui_start(app) -> Ui`; `ui_click(ui: inout Ui, path: String)`;
  `ui_type(ui: inout Ui, text: String)`; `ui_tree(ui: Ui) -> String`;
  `ui_text(ui: Ui, path: String) -> String`; `ui_has(ui: Ui, path: String) -> Bool`. Arguments are
  bare; calls are allowed only in example bodies.
- `ui_start` takes a visual app's bare name and follows M5-01's launch order with no window. A
  headless app is a check-time error.
- The to-do example:

  ```
  example add_one_item {
    var ui = ui_start(todo)
    ui_click(&ui, "'new'")
    ui_type(&ui, "milk")
    ui_click(&ui, "#1")
    ui_text(ui, "'new'") == "" && ui_text(ui, "1/#1") == "milk"
  }
  ```

  Its tree after: `Col gap=8` / `Input 'new' "" cursor=0 on_change=Draft focus` /
  `Button #1 "Add" on=Add` / `Row 1 gap=8` / `Button #0 "[ ]" on=Toggle(1)` / `Text #1 "milk"`.
- Fields: Text, its text; Button, label and `on=`; Input, text, `cursor=`, `sel=a..b`, `preedit=`,
  `on_change=`; Row and Col, `gap=` when not 0; Hole, its name; Error, its message. Shown texts are
  escaped so one node is one line.
- Steps: a negative Int key keeps its `-`; `'` and `\` in a String key are escaped by `\`. A
  placeholder made in a loop is `#n.r`, r counting that line's placeholders in this child list from
  0. A duplicate-key error node carries the key as its step.
- `Hole` and `Error` appear only in tree text and take no names from the pool.
- Each action is handled to the end, view and comparison included, before the call returns.
- `ui_click` on a Button sends its message; on an Input gives focus and puts the cursor at the end;
  on a placeholder makes the example unfinished; on anything else or nothing is a failed-assertion
  trap.
- Each typed code point is one key. A line break or tab in the text is Enter or Tab, which do
  nothing.
- `ui_text` on a Row, Col, error node or nothing is a failed-assertion trap. `ui_has` traps only on
  a badly formed path built at run time.
- The first of these decides the status: hole touched or reached, unfinished; other trap, trapped;
  error node, fail. Otherwise the last line's Bool gives pass or fail.
- Effects are not performed. An allowed effect is dropped; a disallowed one is handled as live. After
  `Exit`, reads see the last tree and any action is a failed-assertion trap.
- No functions for Backspace, arrows, Enter or composing text in M5.
- `Ui` is an owned value, rejected outside example bodies; it cannot be stored or compared.
- Example ownership and caching are not ruled here.
