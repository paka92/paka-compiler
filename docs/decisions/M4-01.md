Status: approved by the owner on 2026-10-15.

Base: the recorded M4-01 page in DECISIONS.md. Every point **stands** as recommended there; this

## 1. The three definitions

[`bench/generators/defs.paka`](../../bench/generators/defs.paka), checked by `paka check`:

| Size | Definition | Lines | Uses |
|---|---|---|---|
| small | `step(x, m; by)` | 7 | match on an enum, Int add and subtract |
| medium | `walk(start, rounds; d)` | 39 | while, if chains, match as a value, calls to `step`, `max`, `sqrt`, `to_float`, `to_int`, divide |
| large | `simulate(seed, rounds; cap)` | 198 | a seven-phase state machine, Float and Int arithmetic, wrapping and bit functions, calls to `step` and `walk`, nested loops with `break`, rounding functions |

No strings, lists or records; their layout is M4-05's.

## 3. What is timed

- **Warm, per definition:** from the checked core form in memory to the first call through the slot
  returning the right value. 20 untimed compiles, then 200 timed ones, each of a fresh copy with one
  constant changed. Median and 95th percentile; three processes, the worst 95th percentile counts.
- **Cold:** from the generator's first call in a new process to the first right result of the
  large definition. One untimed process, then 20 timed; the second slowest counts.
- Idle build machine, one thread, Rust's monotonic clock. Generators measured in the same session
  are interleaved by definition.
- A timing counts only if every expected result above matches and every trap input returns its
  trap status. Each generator's verifier passes once, untimed.

## 4. Generator settings

```
Cranelift: cranelift-codegen + cranelift-frontend, newest release that builds with Rust 1.96.1,
           opt_level=none, verifier off when timed, native ISA;
           code bytes -> mmap, copy, mprotect
LLVM 21:   IR text -> parse -> ORC LLJIT through llvm-c (libLLVM-21.so),
           code generation level None, no passes, one module per definition
both:      every other setting at its default; one context reused
```

Provisional calling convention, for the benchmark only: a compiled definition takes the slot
table's address, a result place and its arguments, and returns 0 or a trap number. A field-less enum
is an integer tag. Calls to definitions and to stand-in runtime functions load their address from
the slot table. Division by zero and the smallest Int divided by -1 are tested before the divide.

## 5. Rule

```
pass = right results
   and warm p95 (large) <= 20 ms
   and cold <= 50 ms
Cranelift is built first. If it passes, it is recorded and LLVM is not built.
Otherwise LLVM is built by this method:
  one passes   -> that one
  both pass    -> Cranelift
  neither      -> lower warm p95 (large), recorded as provisional
```

Also printed, outside the rule: run time of the large definition on `simulate(2026, 2000, cap:
101)`, peak memory, outside crates and unsafe lines per generator.

## 6. Edit benchmark (M4-44)

- Program: 5,000 definitions by default (a command argument), one file per definition, written by
  a fixed-shape generator: the three definitions above, one app, and filler functions of about 20
  numeric lines in a fixed call tree, all reachable from the app.
- Edit classes: body-small, body-medium, body-large (gated at 95th percentile under 100 ms); a
  signature edit with 10 direct users, add, and delete (reported only). A body edit changes one
  constant.
- One sample: one edit request that also asks for a run, from request written to reply read. 200
  per class, three runs, the worst 95th percentile counts.
