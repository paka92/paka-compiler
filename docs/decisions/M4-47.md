# M4-47 · Canonical layout and how tools treat other layouts

Status: approved by the owner on 2026-10-15.

Base: the recorded M4-47 page in DECISIONS.md. All six points **stand** as recommended there.
Section 2 writes out the layout rules with one sample per construct; M4-15's printer implements
them and its golden files follow them.

## 1. Points

| Point | Ruling |
|---|---|
| 1.1 Width | Structure only. Where a line breaks depends on the construct, never on line length. |
| 1.2 Breaks | Blocks broken, lists flat. A block, a match and an app block put one statement, arm or key per line; everything in round or square brackets, a type's fields and an enum's variants stay on one line. |
| 1.3 Comments | Own line, above what they belong to. A comment after code moves above that line; one inside a flat list moves above the statement or definition that holds the list. |
| 1.4 Other layouts | Accepted. Edit stores and returns canonical text; `paka check` judges meaning only; view and find print canonical text whatever is on disk. |
| 1.5 Harmless wrong spellings | Stay errors with their exact fix. Text that parses is stored with the error; text that does not parse is refused. |
| 1.6 Older sources | Left as stored. New hand-written samples, the language reference included, are written in this layout. |

## 2. Layout

The printer changes only white space and where a comment sits. It never reorders, renames, adds or
removes anything else; parentheses stay as written, so `(a * b) + c` stays.

- Two spaces per open block, no tabs, no spaces at line ends, a line feed after every line and one at
  the end of the file.
- One blank line between definitions, none inside a definition. A comment block sits directly above
  what it belongs to.
- No alignment anywhere.
- One space each side of a binary operator and of `=`, `->`, `=>` and `|`; none after `&` or another
  one-operand operator; one space after a comma; none inside round or square brackets.
- Names, strings, numbers and holes print exactly as written.

**type and enum**: one line each; one space inside the braces; empty braces closed up.

```
type Counter { count: Int = 0 }
type Empty {}
enum Msg { Start(path: String), Loaded(text: String) }
```

**fn and example**: header on one line, body always broken. An empty body is `{}` on the header line.

```
fn clamp(x: Int; lo: Int, hi: Int) -> Int {
  max(lo, min(x, hi))
}

example clamp_low {
  clamp(0 - 5, lo: 0, hi: 9) == 0
}
```

**app**: one key per line, keys in the order written.

```
app wc {
  state: Tally
  start: Start
  update: update
  grants: [ReadFiles, Console]
}
```

**Statements**: one per line; `return`, `break` and `continue` each on their own line.

```
let bonus = 10
let n: Int = 0
var sum = 0
sum += x
_ = pop(&q)
return 0
```

**if, for, while**: bodies always broken; `else` stays on the closing brace's line.

```
if x < 0 {
  return x
} else if x == 0 {
  hits += 1
} else {
  sum += x
}
for x in xs {
  sum += x
}
while i < n {
  i += 1
}
```

**match**: one arm per line; an arm whose body is a block breaks like any block.

```
match m {
  Start(path) => [ReadFile(path, then: Loaded)]
  Loaded(text) => {
    s.words = count_words(text)
    [Print("{s.words} words"), Exit]
  }
}
```

**Calls, lists, records, indexing**: always one line.

```
clamp(n, lo: 0, hi: 9)
[Print("done"), Exit]
Counter { count: 1 }
Counter {}
append(&g.next[a], b)
```

**A block inside an expression** breaks where it stands; the `=` or brackets around it add no break.

```
let y = if c {
  1
} else {
  2
}
```

**Signatures and types**: `name: Type`, `-> Int`, `List<Int>`, `Map<String, Int>`, `s: inout Tally`;
the label mark has no space before it and one after: `(x: Int; lo: Int, hi: Int)`.

**Comments**: a comment on its own line stays, also as the last line of a block. A comment after the
last definition joins the comment block above that definition, so a definition added later does not
inherit it.

```
sent     sum += x // running total

stored   // running total
         sum += x
```

Constructs decided later (error handling, ranges, function values, generics, views) follow the same
two rules: a block breaks, a list is flat. The task that decides each one adds its sample here.

## 3. Tools

- Edit rewrites only the edited definition and its comment block; neighbours keep their layout.
  Definition order in a file is kept.
- Text that does not parse has no canonical form; edit refuses it with errors that point into the
  text as sent.
- Hashes come from the parsed definition, never from file bytes, so layout cannot change them.
- No format command is built until a person or script needs one.
