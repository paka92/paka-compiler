# M5-03 · Text input model: text held by the app

Status: approved by the owner on 2026-10-13.

Base: the recorded M5-03 page in DECISIONS.md. All six points **stand** as recommended there.

## 1. Points

**1.1 The app holds the text.** The text is a field of the app's state; the input shows what the
view passes. The element keeps only cursor, selection and text still being composed.

```
type Todos { draft: String = "", items: List<Todo> = [] }
enum Msg { Draft(text: String), Add, Toggle(id: Int) }
fn update(s: inout Todos, m: Msg) {
  match m {
    Draft(text) => s.draft = text
    Add         => add_item(&s)
    Toggle(id)  => toggle(&s, id)
  }
}
// view: Input(s.draft, on_change: Draft, key: "new")
```

**1.2 An edit sends the whole new text** through the variant named in `on_change:`, which has
exactly one String field. An editable list keeps one row being edited in the state until function
values allow a row's input to carry its item id.

**1.3 The app wins; the cursor follows.** The element changes nothing itself: it works out the new
text and cursor and sends the message. If the handler traps or the view hands back the text from
before the key, nothing moves. Any other text is shown, with the cursor where the key put it,
pulled back to the end if the text is shorter.

```
before:          draft = "mil"   cursor 3
key "k"   ->     Draft("milk")
handler traps:   draft = "mil"   screen "mil"   cursor 3
stores as sent:  draft = "milk"  screen "milk"  cursor 4
stores "MILK":   draft = "MILK"  screen "MILK"  cursor 4
refuses:         draft = "mil"   screen "mil"   cursor 3
```

**1.4 Preedit stays in the element until committed.** It is drawn at the cursor, marked as not
final, and sends no message. A commit sends one `on_change` under the same rule as a keystroke. A
change of the app's text moves the preedit with the cursor; it ends on commit, on the IME's cancel,
or when the input loses focus or leaves the tree. Whether IME is in M5 at all is M5-08's.

**1.5 Cursor, selection and focus belong to the runtime.** The app cannot read or set them; they
show in the tree.

**1.6 One cursor step is one code point.** No crate and no download.

## 2. Rules that follow

- The input is `Input(text, on_change: Variant, key: k)`; its full argument list is M5-04's.
- The M5 input is one line; Enter adds no line break.
- When the app sets the text itself, the element shows it, pulls the cursor back to the end if
  needed and clears the selection.
- Arrow keys and pointer moves change cursor and selection and send nothing. Typing replaces the
  selection. A key that would not change the text sends nothing.
- Nothing has focus at launch. Keys with no focused input are dropped.
- Examples observe the text from the state and the tree; cursor, selection, focus and preedit from
  the tree only.
- Keys, clicks and effect results wait in one queue. Each becomes a message only when its turn
  comes, against the tree of that moment, and is handled to the end before the next.
- While the view is trapped, a key is worked out against the text last drawn.
- Each keystroke runs one handler and one view in dev mode.
- Not in M5: clipboard, undo, multi-line text, password fields, a length limit.
