# M2-05 · Ownership: copies, inout exclusivity, borrows, recursive types, changing in place: decision

Base: the recorded M2-05 page in DECISIONS.md, written out as one invariant and four checks, with
the grammar piece, a diagnostic table, the fix text on every refusal and worked samples. All six
recorded picks stand. Two settled lines are made stricter, marked **tightens**; each closes a hole
and refuses nothing the task classes write. Two loosenings that were weighed (String exempt from
the call rule; a `for` that snapshots) are declined, with the reason at the point.

The one invariant: storage is a forest. Every local name (`let`, `var`, parameter, `for` name,
pattern name) is a root; fields, items and entries hang below it. No type names a reference, a
function value carries no data (M2-09), there is no global state. The only sharing that ever exists
is inside one call: a read-only parameter shares the caller's storage and nobody may write it; an
inout parameter shares the caller's storage and only that one name may write it. Every rule below
keeps that true at each call, each loop and each match, by a check that reads one statement.

## 1. Resolutions, point by point

### 1.1 Copies: in meaning, and what a back end may skip

A copy is a new value equal by structure (M2-09) down to every item, entry, field and subtree. In
meaning a copy happens at: `let` or `var` from a place; storing a place into a field, item or entry
(`s.items = xs`, `xs[i] = row`, `m[k] = v`, a record, list or map built from places, the `item` of
`append` inside the callee); returning a parameter or any part of one; binding a `for` name or a
pattern name; the value of an `if`, `match` or block whose last expression is a place. No copy at:
passing an argument, read-only or inout; returning a local (a move); a computed value bound or
stored (moved in). A slice `xs[a..<b]` is a value: a copy when bound or stored, passed without
copying as a read-only argument (M2-05.5).

A back end may skip a copy whenever no write to the source or to the copy can happen while both
are reachable. Every write site is visible (an assignment target or an `&`), so the test is local:
within the statement that holds the copy, no assignment target and no `&` place overlaps the
source (§1.3). Beyond one statement the rule is M4-33's (last use). The interpreter may always copy.

```
fn demo() -> Int {
  let a = [1, 2, 3]
  var b = a            // b is its own list
  append(&b, 4)
  len(a)               // 3
}
```

Why not move-and-copy-by-name (Rust): use-after-move errors cost counted edits and M2-21 would need
move tracking. Why not shared-until-written (Swift): a count on every value and a check on every
write in native code (line 85). This is M2-05.1 as recorded.

### 1.2 Places, fresh values and the exemption

A place is a local name followed by steps: `.field`, `[index]` on a List or Map, `[a..<b]` on a List
or String. Parentheses change nothing; a slice step counts as an index step and steps after it still
count (`xs[0..<2][0]` is rooted at `xs`). Everything whose root is not a name is a fresh value and
overlaps nothing: a literal, a call result, an operator result, an `if` or `match` value, a built
list, map or record, an interpolated string, `e?`, a hole.

A place-rooted read of type Int, Float or Bool is a fresh value: the back end reads it into a
register when it is evaluated, so no pointer into the source survives. **String is not exempt.**

Why not String too: the exemption holds for exactly the types a back end carries in a register. A
String is heap storage of any length; to exempt it a back end must either borrow it across the call
(unsound when the `&` argument changes it) or copy it before the call, a hidden copy whose size the
source does not show (`log(&s, s.text)` in a loop copies the document every step). The refusal has
a one-line fix in its message, the practice runs count it (M3-03), and lifting it later breaks no
program; adding it now and taking it back would. It is the first loosening to weigh after the runs.

### 1.3 The overlap test

Two places overlap unless they have different roots, or their steps first differ at two different
field names. As an algorithm, with the two step lists walked side by side:

1. Different root names: apart. Stop.
2. Take the next step of each. If either list has no step left: overlap. Stop.
3. Two field steps with different names: apart. Stop. Two field steps with the same name: continue.
4. Any index or slice step against any index or slice step (List or Map; index values are not
   compared): overlap. Stop.
5. A field step against an index step cannot happen: the types differ. Continue defensively.

```
p.left        vs  p.right        apart    (fields differ)
p             vs  p.right        overlap  (prefix)
rows[0]       vs  rows[1]        overlap  (index steps never part ways)
g.nodes[a].x  vs  g.nodes[b].y   overlap  (differ first at an index step)
xs            vs  ys             apart    (different roots)
xs[0..<2]     vs  xs[1]          overlap  (slice counts as index)
m[a].balance  vs  m[b].name      overlap  (Map entries, M2-14)
```

Why literal indexes do not part ways: one test for `rows[0]`/`rows[1]` and `rows[i]`/`rows[j]`, or
the rule has two tiers to learn. "Same let index, then fields apart" and a run-time `overlap` trap on equal
indexes are both sound loosenings that can be added later without breaking a program; neither is
taken now. This is M2-05.3 as recorded.

### 1.4 The `&` mark and what may follow it

`&` is written on every inout argument and nowhere else: only as a whole argument of a call, bare or
labelled (§2). What may follow it: a `var` local or an inout parameter, with any number of field
steps and List or Map index steps (M2-14: `&m[key]` needs the key). Not: a `let`, a read-only
parameter, a `for` name, a pattern name, a slice, a String position, a computed value. A call through
a function value takes no `&` (M2-09: no inout in a function type). An `&` anywhere but an argument
position is `unexpected-inout-mark`.

```
let a = [1]
append(&a, 2)                                 // bad-inout-target at a: "a is a let; declare it with var"
var a = [1]
append(&a, 2)                                 // accepted
fn f(xs: List<Int>) { append(&xs, 1) }        // bad-inout-target: "xs is read-only; write xs: inout List<Int>
                                              //   and call f(&ys)"
fn f(xs: inout List<Int>) { append(&xs, 1) }  // accepted
for x in rows { append(&x, 1) }               // bad-inout-target: "x is a for name; it is a copy"
append(&xs[0..<2], 1)                         // bad-inout-target: "a slice cannot be passed with &; pass
                                              //   the list and the positions"
append(&text[i], "a")                         // bad-inout-target: "a String position is not a place"
append(xs, 1)                                 // missing-inout-mark at xs: "append changes xs: write &xs"
less(&a, b)                                   // unexpected-inout-mark: "less is a function value and takes
                                              //   no inout; drop the &"
let r = &xs                                   // unexpected-inout-mark: "& is written only on an argument"
```

### 1.5 The call rule

Checked once per call from the callee's signature and the operands' types; nothing outside the one
statement is read. Operands are evaluated left to right (M2-03).

- **Rule A (inout against the rest).** An `&` place may not overlap any other place-rooted,
  non-exempt operand of the same call, read-only or `&`. Error `inout-overlap`.
- **Rule B (read-only against sibling writes). tightens.** A read-only, place-rooted, non-exempt
  operand may not overlap any place *written* anywhere inside a sibling operand's subtree. Written
  means passed with `&` to a target §1.4 allows, or used as an assignment target (a block inside an
  `if` or `match` value holds statements). The order of the siblings does not matter. A String key
  read inside an `&` place's index expressions counts as a read-only operand of the call for this
  rule. Error `changed-while-read`. The recorded line named `&` only; the assignment form is the
  hole it left.
- **Rule C (what counts as a call). tightens.** Rules A and B apply to every form with several
  operands evaluated in order: a call's arguments, an operator's two operands, a list literal's
  items, a map literal's keys and values, a record's fields and an interpolation's parts. The
  recorded line named operators only. A call through a function value counts its callee expression
  as one more operand. Assignment is not a call (§1.6).
- **Rule D (lookup time).** An `&` place evaluates its index expressions with the other operands;
  the place itself is resolved, with its bounds or key check, when the call starts. A read-only
  place-rooted operand likewise evaluates its index expressions, then walks; a missing item or key
  traps `out_of_bounds` at that `[`. A write nested inside an operand's own index expression
  therefore finishes before that operand's read.

Why order-free: `merge(take(&xs), xs)` aliases nothing in the interpreter, but one condition is
simpler than two and the fix is the same line. Why Rule C: a list literal or interpolation is a call
to the back end; a pointer taken for `xs` in `[xs, take(&xs)]` is the same pointer as in a call.

Accept and reject (`append`, `grow`, `swap_lists`, `take`, `merge`, `push`, `f`, `g` take their
first argument inout; `xs`, `names`, `rows`, `p`, `st`, `s`, `m` are `var` or inout):

```
grow(&xs, xs)                   // inout-overlap at xs: "xs is passed with & and read in one call;
                                //   bind it first: let old = xs"
let old = xs
grow(&xs, old)                  // accepted: old is its own root
append(&xs, xs[0])              // accepted: an Int is read before the call
append(&names, names[0])        // inout-overlap: String items; "bind it first: let first = names[0]"
append(&xs, len(xs))            // accepted: a call result is fresh
grow(&p.left, p.right)          // accepted: fields differ
grow(&rows[0], rows[1])         // inout-overlap: "two items of rows in one call; bind one first"
swap_lists(&p.left, &p.left)    // inout-overlap: "p.left is passed with & twice"
swap_lists(&p.left, &p.right)   // accepted
grow(&xs, xs[0..<2])            // inout-overlap: a slice of xs is xs
apply(&s, s.rules[i])           // inout-overlap: "bind it first: let rule = s.rules[i]"
apply(&s, s.count)              // accepted: Int
merge(xs, take(&xs))            // changed-while-read at xs: "xs is read by merge and changed by
                                //   take(&xs) in the same call; bind it first: let old = xs"
merge(take(&xs), xs)            // changed-while-read: order does not matter
f(&m[k], g(&k))                // changed-while-read at k: the key is read before the call starts;
                                //   "bind it first: let key = k"
f(xs, if c {                    // changed-while-read: an assignment inside a sibling
  xs = []
  1
} else { 0 })
xs == f(&xs)                    // changed-while-read: operands count
"{s} {take(&s)}"                // changed-while-read: interpolation parts count
[xs, take(&xs)]                 // changed-while-read: list items count
Pair { a: xs, b: take(&xs) }    // changed-while-read: record fields count
xs[0] == pop(&xs)               // accepted: Int, read first
push(&st, pop(&st) + pop(&st))  // accepted: the pops finish before push starts
f(&xs[i], g(&xs))               // accepted: g runs, then xs[i] is resolved (Rule D); a vanished
                                //   item traps out_of_bounds at the [
f(&xs[pop(&xs)], 1)             // accepted: the index is an Int before the lookup
f(xs[pop(&xs)], 1)              // accepted: the write is inside the operand's own index
transfer(&m[a], &m[b])          // inout-overlap: "two entries of m in one call; write
                                //   transfer(&m, a, b)"
move_n(&m[a], m[b].balance)     // accepted: Int
```

Of twenty lines written first by habit for the M2-01 task classes, these rules refuse nine:
`append(&names, names[0])`, `apply(&s, s.rules[i])`, `grow(&g[r], g[r-1])`, `transfer(&m[a],
&m[b])`, `for v in g.adj[u] { dfs(&g, v) }`, `for x in q { append(&q, f(x)) }`, `&` on a
pattern-bound name, `extend(&xs, xs)`, `expect(&p, p.toks[p.pos])`. Each message carries a one-line
fix; the two loop lines are refused on purpose (§1.7); the others are the price of no hidden
aggregate copy. Copying silently would refuse three and hide a List copy in every simulation step.

### 1.6 Changing in place

An assignment target and an `&` target are the same set: a `var` local or an inout parameter through
any depth of field steps, List items and Map entries: `g[r][c] = v`, `s.items[i].count += 1`,
`m[k].balance -= n`, `append(&g.next[a], b)`, `append(&m[k], x)`. A `let` is fixed all the way down
(`assign-to-let`). A missing List item traps `out_of_bounds` at the store; only the last step of a
plain `=` may add a Map key (M2-14). The fields of a variant are not places: a value inside `Some`,
`Ok`, `Err` or a user variant is changed by matching, building and assigning the subject
(`bad-assignment-target`, extended message). There is no place step through an Option or Result.

Assignment order (M2-03): the target's index expressions, the right side, then (for `+=`) the read,
the operation, the write. An assignment holds no access across its right side, so `xs[i] = f(&xs)`
and `xs[len(xs) - 1] = pop(&xs)` are accepted and run f or pop first, then store with the bounds
check at the store. The store copies the right side before the target's old value is released, so
`n = n.kids[0]` and `xs[i] = xs[j]` are defined when the two sides overlap.

Two items are swapped by `swap(&xs, i, j)` (M2-14) or three assignments; `swap_items(&xs[i],
&xs[j])` with a user function is Rule A, even when i != j.

```
enum Shape { Dot, Rect(w: Int, h: Int) }
type Cell { shape: Shape = Dot, hits: Int = 0 }

fn touch(c: inout Cell, grid: inout List<List<Int>>, m: inout Map<String, Cell>) {
  c.hits += 1                            // accepted
  grid[0][1] = 7                         // accepted
  m["a"].hits += 1                       // accepted when "a" is present; else traps
  m["b"] = Cell {}                       // accepted: a plain store may add a key
  match c.shape {
    Dot        => c.shape = Rect(1, 1)   // accepted: the arm assigns the subject
    Rect(w, h) => c.shape = Rect(w * 2, h)
  }
  c.shape.w = 3                          // bad-assignment-target: "w is a field of the variant Rect;
                                         //   build Rect(..) and assign c.shape"
}
fn transfer(m: inout Map<String, Account>, a: String, b: String, n: Int) {
  m[a].balance -= n                      // accepted: two entries changed in one step, two statements
  m[b].balance += n
}
```

### 1.7 `for` and `while`: the walked place is frozen

The `for` name is a read-only value, a copy in meaning of the item. When the walked expression is a
place, the body may not write any place overlapping it: no assignment target and no `&` anywhere in
the body's subtree, including a prefix (`&g` while walking `g.adj[u]`) and an item (`xs[0] = x`).
When the walked expression is fresh (`keys(m)`, a call result, a slice bound first, a range), the
body may change anything. `while` freezes nothing. Error `changed-while-walked` at the write.

```
for x in xs { append(&xs, x) }             // changed-while-walked at &xs: "xs is walked by this for;
                                           //   walk a copy (let items = xs, then for x in items) or
                                           //   by position (for i in 0..<len(xs))"
for x in xs { xs[0] = x }                  // changed-while-walked at xs[0]
for v in g.adj[u] { dfs(&g, v) }           // changed-while-walked at &g: g is a prefix of g.adj[u]
for v in g.adj[u] { append(&g.adj[w], v) } // changed-while-walked: items never part ways
for it in s.items { s.total += it.price }  // accepted: fields apart
for x in s.items { s = S {} }              // changed-while-walked: s is a prefix
for i in 0..<len(xs) { xs[i] += 1 }        // accepted: a range is fresh; len evaluated once (M2-03)
for k in keys(m) { remove(&m, k) }         // accepted: keys(m) is a fresh List (M2-14)
let next = g.adj[u]
for v in next { dfs(&g, v) }               // accepted: next is its own root
for row in g { row[0] = 1 }                // assign-to-let: "row is a for name; write g[i][0] = 1
                                           //   walking by position"
var i = 0
while i < len(q) {                         // accepted: a growing queue
  let x = q[i]
  i += 1
  append(&q, next_of(x))
}
```

The DFS idiom the reference shows keeps the visited list as its own parameter, which needs no copy:

```
fn dfs(g: Graph, seen: inout List<Bool>, u: Int) {
  seen[u] = true
  for v in g.adj[u] {                      // g is read-only: nothing in the body can write it
    if !seen[v] { dfs(g, &seen, v) }       // accepted: seen is another root
  }
}
```

Why frozen, not a snapshot: a snapshot is the meaning "loop sees old items", under which a queue
loop that appends to its own list stops early without a word and a helper reached through `&g`
grows the walked list silently. The recorded pick refuses instead, lifting is free later, and the
back ends keep walking the caller's storage by index with no copy and no tag (M2-26: "needs no
snapshot"). The two loop lines in the refusal count cost one edit each; the fix is in the message,
and the DFS idiom above costs nothing.

Why item writes are refused as well as growth: the interpreter walks without a snapshot and native
code walks the buffer by index; a write the body makes to an item would change what a by-reference
walk sees next, and the two back ends must agree.

### 1.8 `match` arms: pattern names are values

A pattern name is a read-only value, a copy in meaning of the field, bound when the arm is chosen.
The arm may assign to the subject's place or pass it with `&`. Back-end rule, not a language rule: a
back end may bind the pattern names by reference into the subject only in an arm whose body holds no
write (assignment target or `&`) to a place overlapping the subject, anywhere in the arm's subtree;
in any other arm it copies the bound fields at arm entry, before the body runs. The interpreter may
always copy. The same test applies to `e?`: its payload is copied out when the statement holding it
writes a place overlapping `e`.

```
fn widen(s: inout Shape) {
  match s {
    Dot        => {}
    Rect(w, h) => s = Rect(w + 1, h)       // accepted; w, h copied at arm entry (both Int: registers)
  }
}
fn left_of(e: inout Expr) {
  match e {
    Num(v)           => {}
    Add(left, right) => e = left           // accepted; left copied at entry, e released, copy stored
  }
}
match s.kind { Big(n) => s.count = n }     // s.count and s.kind apart: n may be borrowed
match s {                                  // accepted; w copied at entry, so a is sound
  Rect(w, h) => {
    s = Dot
    let a = w
  }
}
```

Why not pattern names as places: in-place enum trees, but a second exclusivity rule inside the arm
and a copy of the subject on every arm that assigns; no task class needs it. Why not freezing the
subject in the arm: it refuses the state-machine step, where an arm sets the state it matched on.

### 1.9 Finite values, storage, borrows, results, function values

- **Finite value.** A type is grounded when: Int, Float, Bool, String, List, Map and function types
  are grounded; a record is grounded when every field is; an enum is grounded when at least one
  variant has only grounded fields (Option and Result are enums). Computed as a least fixed point over
  the program's types; an ungrounded type is `no-finite-value` at its name. Only types on a by-value
  cycle are reported; a type that merely holds one is not.
- **Storage.** A field whose type holds the enclosing type by value is stored behind a pointer the
  program never sees (which fields: M4-22; a List already is one). The tree is one owned value: copy
  and compare are deep, release runs as a loop with a worklist and never overflows the stack; a copy
  or compare too deep for the back end traps `stack` (M2-06). An enum tree is changed by building the
  changed tree; a record tree is changed in place through fields and indexes (`&n.kids[i]` in a
  recursive call is the idiom).
- **Borrows.** No type names a borrow. A read-only parameter can be read and passed on read-only; it
  cannot be assigned, passed with `&` or kept without a copy. A borrow lives exactly one call; no
  lifetime exists. Two parameter kinds only; a third can be added later.
- **Results.** A function returns an owned value: a local moves, a parameter or part of one copies
  (the case the paper warns Swift reaches for, line 429; the copy is visible as a return of a
  parameter).
- **Release.** A value is released when its owner goes out of scope or is overwritten; nothing
  observable runs, no destructors, releasing never traps.
- **Function values.** A name and nothing else (M2-09). If closures are ever added they capture by
  copy at creation and never an inout parameter as a place, or every rule here breaks.

```
type Node { next: Node }                      // no-finite-value: "Node holds itself through next with
                                              //   nothing between; write next: Option<Node> or put it
                                              //   in a List or an enum variant"
enum Chain { Link(next: Chain) }              // no-finite-value
type Node { next: Option<Node> = None }       // accepted
type Node { kids: List<Node> = [] }           // accepted
enum Chain { End, Link(next: Chain) }         // accepted
enum Expr { Num(value: Int), Add(left: Expr, right: Expr) }   // accepted
```

### 1.10 Counter-examples tried against the rules

1. `f(&xs, id(xs))`: `id` returns a copy of its parameter, fresh before f starts. Harmless.
2. Two names on one storage through a function value: impossible, it carries nothing.
3. `swap_items(&xs[i], &xs[j])`: Rule A.
4. `for row in grid { append(&grid, row) }`: §1.7, before any question of `row` arises.
5. The arm writes `s`, so `w` is copied at entry:
   ```
   Rect(w, h) => {
     s = Dot
     use(w)
   }
   ```
6. `f(&g.nodes[a].edges, g.nodes[b].name)`: §1.3, index steps never part ways.
7. Recursion `fn f(xs: inout List<Int>, ys: List<Int>) { f(&xs, ys) }`: distinct roots inside;
   the caller proved them apart; induction over the stack. `f(&xs, xs[0..<1])` inside: Rule A.
8. Rule B, both forms: `merge(xs, take(&xs))` and
   ```
   f(xs, if c {
     xs = []
     1
   } else { 0 })
   ```
9. `f(&xs[i], g(&xs))`: Rule D resolves `xs[i]` after g with a bounds check; no dangling pointer.
10. `"{s}{take(&s)}"`, `[xs, take(&xs)]`: Rule C.
11. `g(xs[0..<2], h(&xs))` inside `f(xs: inout ...)`: Rule B.
12. b is a copy; a unchanged:
    ```
    let b = id(a)
    append(&b, 1)
    ```
13. `fn f(xs: inout List<Int>) { for x in xs { pop(&xs) } }`: §1.7; `xs` is the only path.
14. `f(&m[a], m[b])`: §1.3. `f(&m, m[b])`: prefix. `f(&m[a], get(m, b))`: `get` copies first.
15. `?` leaving early mid-evaluation: evaluated operands are released; no `&` place is resolved yet.
16. A hole in an argument: traps before the call.
17. A trap inside a handler while an `&` place is held: a headless app ends (M2-15), so the held
    place is never seen; no state copy is taken.

## 2. Grammar (additions to M2-02 §2)

```
args        = [ arg { "," arg } ] [ [ "," ] labelled { "," labelled } ]
arg         = expr | "&" place
labelled    = LOWER ":" ( expr | "&" place )
place       = LOWER { "." LOWER | "[" expr "]" }      (* unchanged; a range inside [ ] is a slice step,
                                                        refused after & by the checker *)
```

`"&" place` leaves `primary`. `param = LOWER ":" [ "inout" ] type` stays; no type mentions inout.
The `for` header, the `match` subject and the assignment target keep M2-02's grammar; the checker
classifies each as a place or a fresh value by §1.2. The `&` token and M2-02 §1.5 (not a two-sided
operator) are unchanged.

## 3. Implementation rule: interpreter and native code

Both back ends give the same answers because every rule is syntactic and the meaning is copies.

**Interpreter (M2-26).** Values are owned trees (Int, Float, Bool, String, a vector for List, an
ordered map for Map, boxed payloads for self-holding types). Copy on bind from a place, on store, on
return of a parameter; pass read-only arguments by reference or by copy, either is correct. An
inout argument: evaluate its index expressions with the other operands, then at call start resolve
the path to the slot with its bounds or key check and hold that slot for the call; the callee reads
and writes through it. Because nothing can reach overlapping storage during the call, an
implementation may equally move the value out of the slot at call start and back at return. No
snapshot for `for`; pattern names may always be copied; deep release by a worklist loop; a depth
count on copy and compare that traps `stack`.

**Native (M4-05, M4-22, M4-33, M4-34, M6-23).** Scalars by value; a read-only List or String
parameter as pointer and length (so a slice is passed as a part); other read-only aggregates by
pointer; an inout parameter as a pointer to the resolved place. Regions a back end may borrow
across, each guaranteed by a refusal above:

| Region | Borrow | Guaranteed by |
|---|---|---|
| A read-only argument, for the call | pointer (and length) | Rules A, B, C; §1.9 borrows |
| An inout argument, for the call | pointer to the resolved place | §1.4, Rules A, D |
| The walked place, for the whole `for` | pointer and index | §1.7 |
| Pattern names, in an arm that writes nothing overlapping the subject | pointers into the payload | §1.8 |
| A `let` bound from a place, until its last use, with no overlapping write before it | pointer | §1.1, M4-33 |
| Int, Float, Bool anywhere | register copy | §1.2 |

Copies a native back end must make: a bind from a place that is written later (or always, until
M4-33 lands); a store of a place into a field, item or entry, made before the old value is released;
a return of a parameter or part; pattern names in a writing arm; a callee storing a read-only
parameter. Release mode may mark inout parameters `noalias` on the strength of Rule A alone; that is
M6-23's signature to give, with M6-22's run as evidence. M6-22a's detector checks two things: at
each call start no inout argument shares storage with another argument, and no read-only place
argument was written between its evaluation and the call's return.

**Core form (M2-23).** A place node with index operands evaluated before the walk; a call node that
resolves `&` places after all operands; no borrow node.

## 5. New diagnostic codes

Check (status 1, at the named token; each message ends in the repair):

- `missing-inout-mark` at the argument: "F changes NAME: write &NAME".
- `unexpected-inout-mark` at `&`: "NAME is read-only in F; drop the &" / "F is a function value and
  takes no inout; drop the &" / "& is written only on an argument of a call".
- `bad-inout-target` at the token after `&`: "NAME is a let; declare it with var" / "NAME is
  read-only; write NAME: inout T and call F(&ys)" / "NAME is a for name; it is a copy" / "NAME is a pattern name; it is a copy"
  / "a slice cannot be passed with &; pass the list and the positions" / "a String position is not
  a place" / "only a var local, an inout parameter or their fields and items can be passed with &".
- `inout-overlap` at the later of the two operands: "NAME is passed with & and read in one call;
  bind it first: let old = NAME" / "two items of NAME in one call; bind one first" / "two entries of
  NAME in one call" / "NAME is passed with & twice". Which form, by where the two places first
  differ as written: nowhere, or one ends first, gives "passed with & twice" (two `&`, NAME the
  shorter) or "passed with & and read" (NAME the `&` place, the `let` binding the read place); at
  an index step gives "two items" (List) or "two entries" (Map) of the collection, ending in "bind
  one first" against a read and in "write F(&NAME, A, B)" against a second `&`, with the two
  indexes as written; when one does not fit on the line, end in "bind one first". A `let` fix whose
  expression does not fit on the line ends at "bind it first". The `let` name: `old` for a bare name, the field's name after a field, `part` after a slice,
  `first` after `[0]`, else the collection's last name without a final `s` (`item` when there is
  none): `let first = names[0]`, `let rule = s.rules[i]`.
- `changed-while-read` at the read-only operand: "NAME is read by F and changed by G(&NAME) in the
  same call; bind it first: let old = NAME" (the assignment form names the assignment). F is the
  callee, the operator, the record's name or "this list" / "this map" / "this text"; the `let` name
  follows `inout-overlap`.
- `changed-while-walked` at the write (`&` or the target's first token): "NAME is walked by this
  for; walk a copy (let items = NAME, then for x in items) or by position (for i in
  0..<len(NAME))", with the loop's own name for x.
- `no-finite-value` at the type name: "T holds itself through FIELD with nothing between; write
  FIELD: Option<T> or put it in a List or an enum variant".
- `bad-assignment-target` (M2-02, extended message): "FIELD is a field of the variant V; build
  V(..) and assign SUBJECT", SUBJECT the subject as written (`assign c.shape`, §1.6).

Kept and reused: `assign-to-let` (a `let`, parameter, `for` name or pattern name as a target; a
`for` name that walks a place with no slice step, rooted at a `var` or inout parameter, takes
§1.7's text: "NAME is a for name; write PLACE[i]REST = VALUE walking by position", REST the target's
steps after NAME, `=` the assignment's operator; otherwise the plain text),
`out_of_bounds` and `stack` as trap kinds (M2-06). No trap kind is added; a run-time `overlap` trap
is the reserved loosening of §1.3.
