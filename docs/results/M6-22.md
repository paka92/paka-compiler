# M6-22 · The inout overlap run

Command: `cargo test --release --offline -p paka --lib overlap_run -- --ignored --nocapture`
(`PAKA_OVERLAP_SEEDS=N` for another count). It is the ignored test
`accepted_calls_never_overlap_in_a_million_programs` in paka/src/interp/overlap_run.rs. For each
seed it checks `paka_gen::program_with_overlaps(seed)`, and when the checker accepts it, runs it on
the interpreter with the overlap detector on (M6-22a, `interp::run_watched`).

| Programs | Refused for an overlap | Accepted | Same-value calls | Flagged | Time |
|---|---|---|---|---|---|
| 1,000,000 | 96,617 | 903,383 | 140,910 | 0 | 310 s |

A same-value call is a call run in an accepted program that took an inout argument together with
another argument from the same local: a second `&` place in it or a read-only part of it. The
detector counts each one as it starts. Every refused program was refused with `inout-overlap`;
no program was refused for anything else.

## What the generator passes beside an `&` place

In `program_with_overlaps` the arguments beside an `&` place (another argument of the call, the
item of `append` or `insert`, the List of `extend`) are often drawn from the place's own local:

- a field: `f(&v.x0, v.x1)`, apart at a field, or deeper, `f(&v.x0.x1, v.x0.x2)`;
- a List item: `append(&v, v[0])`, and an item reached through fields;
- a slice: `extend(&v.x0, v.x1[0..<min(1, len(v.x1))])`;
- a Map entry: `f(&v.x0, v.x1["a"])`.

Half the time any part of the local may be drawn, prefixes and overlapping items included, so the
checker must refuse those programs; otherwise only parts M2-05 accepts are drawn (an Int, Float,
Bool or function value anywhere in the local, else a part apart at a field). A function's other
parameters mostly take the type of a part of its first inout, so such calls are common.
`paka_gen::program` is unchanged: its programs are the same for every seed.

Pool nodes do not exist: Paka has no pool or handle (M2-10, M2-14), so no case uses one.

## With Rule A off

A test-only switch (`RULE_A_OFF`, `cfg(test)`, read only in `inout_overlap` in
paka/src/body/own.rs) turns off the `inout-overlap` check. With it off, the small run
(`with_rule_a_off_the_small_run_flags_an_overlap`, seeds 0 to 1,999) refuses nothing for an
overlap, and the detector flags calls in many accepted programs. The same seeds with every rule on
(`accepted_calls_never_overlap_in_a_small_run`) flag nothing. Both run in the normal tests.

## Hand-written cases

New cases in tests/conformance/ownership: `overlap_deep_prefix`, `overlap_option_field` (an Option
part is not exempt), `overlap_read_is_prefix`, `read_field_changed_by_prefix`, `read_key_marked`,
`read_written_in_sibling_if_apart` and `same_value_arguments` (fields apart at depth, two `&` places
apart, a slice, a Map entry and Int, Float and Bool items beside an `&` place, a function-value
field, and a nested literal that copies a place before a sibling changes it). Together with the
existing cases they cover every rule and sample of M2-05.

`read_key_marked` (`put(&m[k], &k)`) found a hole in Rule B: a String key inside one `&` place's
index was not checked against another `&` argument of the same call. The checker now refuses it
with `changed-while-read`.
